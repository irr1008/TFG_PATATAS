# Gestión ágil del proyecto

## Metodología seleccionada

El proyecto se gestionará mediante una adaptación individual de Scrum combinada
con elementos visuales de Kanban y planificación temporal mediante diagramas de
Gantt.

Esta adaptación se realiza porque el TFG será desarrollado por un único
estudiante con supervisión periódica del profesor.

## Adaptación de Scrum

Se utilizarán los siguientes elementos:

- Product Backlog.
- Sprint Backlog.
- Objetivo del sprint.
- Planificación del sprint.
- Revisión del sprint.
- Retrospectiva del sprint.
- Incremento funcional.
- Registro de impedimentos.

El alumno asume la planificación, el desarrollo, la gestión del backlog y
la revisión inicial. El profesor supervisará el progreso, validará la dirección
del proyecto y revisará los incrementos obtenidos.

## Flujo Kanban

El tablero utilizará los siguientes estados:

1. Backlog.
2. Por hacer.
3. En progreso.
4. En revisión.
5. Bloqueado.
6. Hecho.

## Límite de trabajo en curso

Se establece un máximo de una tarea en estado `En progreso`.

Este límite pretende reducir los cambios de contexto y favorecer la finalización
de una tarea antes de comenzar otra.

## Planificación mediante Gantt

ProjectLibre se utilizará para crear la planificación temporal formal del TFG.

El diagrama de Gantt incluirá:

- Fases del proyecto.
- Tareas.
- Duraciones.
- Fechas de inicio y finalización.
- Dependencias.
- Hitos.
- Revisiones con el profesor.
- Fecha prevista de entrega.

## Relación entre herramientas

Las GitHub Issues representarán las tareas concretas. Los GitHub Milestones
agruparán fases principales. GitHub Projects se utilizará para el backlog, el
tablero Kanban y el roadmap.

ProjectLibre se utilizará para representar la planificación temporal formal y
generar el diagrama de Gantt.

Los nombres de las tareas y de los hitos se mantendrán coherentes entre GitHub
y ProjectLibre.

## Definición de tarea terminada

Una tarea se considerará terminada cuando:

- Existe la implementación o el documento.
- Se ha comprobado el resultado.
- Se han guardado los resultados relevantes.
- Se ha actualizado la documentación.
- Se ha creado un commit descriptivo.
- La issue relacionada se ha cerrado.
- La tarea se ha movido a `Hecho`.
- Se ha actualizado la planificación si ha habido una desviación.
